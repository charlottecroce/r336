Developer Guide

Pipeline

source  →  lexer  →  parser  →  analyzer  →  codegen  →  JS

A file passes through those four stages. A project of more than one file adds a module graph pass in front of them, because a module has to be at least partly understood before the file that imports it can even be parsed.

The lexer (lexer.js) does more than tokenize. R336 word order is VSO. A statement that opens with a known imperative is a command. a <briathar> only parses as a verbal noun if <briathar> is a known verb. Both of those decisions need a lexicon before the parser can make them. So the lexer runs a pre-scan of the token stream first and builds two sets: gniomhartha (every imperative) and briathra (every declared verb, of either mood). This mirrors how a reader of Irish already knows which words are verbs before they can parse VSO word order. A reader working from another text's vocabulary has to read that text first, which is exactly why a module's own lexicon has to exist before the file that imports it is parsed.

The lexer also treats tar éis as one frozen token rather than two separate words. Irish marks completed aspect with a fixed prepositional phrase, and a reader of Irish reads it as one unit too. For a saor declaration the pre-scan does extra work. It derives the verb's autonomous surface form right there, using the same conjugation rules described under Mood and aspect below, and adds both the root and the derived form to the lexicon. The root goes in so that commanding it by mistake still parses. It gets refused by name later (E518) instead of failing to parse at all. Diagnosing a mistake is a better outcome than being unable to read the program that contains it.

A multi-file project builds its module graph with Tionscadal in modúil.js. Each module's dependencies are compiled first, or at least reduced to a signature, because the imported lexicon has to exist before the importing file can be parsed. The compiler keeps a stack of paths currently being compiled and a cache of finished ones, keyed by absolute path. A path still on the stack when it's revisited is a circular import (E110). A path that never resolves to a file is E109. The filesystem itself is injected as a small interface, { ann, léigh }, so the same pipeline runs against a real filesystem or against an in-memory map in tests. Each compiled module is cached as { js, ast, anailiseoir, siniu }, and a dependant only ever needs the siniu (signature) to be checked against, which is what lets the graph compile bottom-up: leaves first, their signatures cached, then whatever imports them.

The parser (parser.js) is recursive descent. Its AST keeps grammatical categories instead of machine operations. ainm ó dhuine becomes a possessive node with a ball (member) and a sealbhóir (possessor). It does not become a member-access node. scríobh x becomes a command node, not a function call. Lowering to JavaScript shapes happens only in codegen, nowhere earlier. One precedence decision is worth naming on its own: ó binds tighter than a function call. beannacht ó dhuine(x) applies the argument to the whole noun phrase beannacht ó dhuine, which reads as a method call, because in Irish ó dhuine is a constituent of the phrase around it rather than something a following call could reach past. The cost is that a call sitting inside a possessive chain needs parentheses of its own: ainm ó faigh(id).

The analyzer (analyzer.js) runs six passes over one file's AST, always in the same order. Pass 0 brings in the imported lexicon before anything local is declared, so a local name that collides with an import is caught as an ordinary redeclaration rather than needing its own rule. Pass 0b reads the file's own as declaration, because nothing else can be judged against a county until the accessing side has one. Pass 0c registers this file's treaties, so an access anywhere in the file can rely on a treaty written anywhere else in it, regardless of order. Pass A hoists every struct, sum, and verb declaration, so a verb may call another verb that is declared later in the file. Pass A2 resolves field types and verb signatures once every name exists, so a call may syntactically precede the verb it calls. Pass B walks top-level statements in the order they were written. Pass C walks every verb body last, with the whole global scope already in view. Splitting hoisting from body-checking this way is what lets two verbs call each other regardless of which one appears first on the page, with no separate forward-declaration syntax needed.

Within each of those passes, the analyzer does four jobs at once rather than in four separate tree walks: ordinary type checking; government (which grammatical form a syntactic slot demands of the word filling it); agreement (does the surface form actually written match that demand); and mood and aspect checking (may this verb be mentioned here at all, is it being completed correctly). A single call to slonn(), the expression-walking method, resolves all four for every node it visits. That follows directly from the linguistic model behind the language. Government and agreement are not a system bolted onto a semantic core in Irish. They are one fact about a word's environment, seen from two angles, and the analyzer treats them that way.

Codegen (codegen.js) erases everything grammatical. By the time it runs, lenition is already gone, because dhuine was resolved to the lemma duine back in the analyzer. Mood is gone, because an imperative is now just a plain function. Aspect is gone, because ag became async and tar éis became await while the analyzer was still checking the file. A má/mura chain compiles to a ternary when every branch is a single expression with nothing to hoist, and falls back to an if/else assigning into a hoisted temporary (let __t0) the moment any branch contains its own statements. If codegen needed to know which surface form the programmer actually wrote, the grammar would only be a find-and-replace wearing a costume. Every feature ships a test that asserts nothing grammatical leaks into the generated JavaScript, and that check is treated as part of the feature, not an afterthought.

Government and agreement, the one idea everything follows

Four operators demand a grammatical form of the word right after them. One function checks all four.

OperatorDemandsExample
ólenitedainm ó dhuine
arlenitedcuir 3 ar chomhaireamh
aleniteda fhógair
asbaseas Corcaigh

That function is reitighFoirm. It takes three things: the surface form actually written, the grammatical form the position demands, and a predicate asking whether a given lemma is known in scope. It first works out the most likely lemma behind the surface form, stripping a leading séimhiú if the word looks lenited. It checks whether that lemma is known. Then it compares the surface form against what the demanded form should look like for that specific lemma. A mismatch is reported with the exact reason: lenited where the position wants the base form, base where the position wants lenited, lenited spelling of a word that structurally cannot lenite at all, or a form that matches no known paradigm of that lemma. ó, ar, and a all call this function asking for the lenited form. as calls it asking for the base form. That is the entire mechanism behind government in the language: four call sites into one shared check, nothing more.

Only the nine consonants b c d f g m p s t can carry a written séimhiú. It is spelled by prefixing h, with case preserved: duine becomes dhuine, Duine becomes Dhuine. Vowels and l n r h cannot lenite at all. The base form is correct after any of the operators above when the word has nowhere to go. That is not an exception. It is the same rule applied to a word with an empty mutation slot. s lenites before a vowel or l n r, and resists it in sc- sf- sm- sp- st- clusters.

A binding is one symbol-table entry with a paradigm attached to it. It is never split into duine and dhuine as two separate names. The surface form is checked against what the position demands, and the lemma is what actually gets bound and carried forward. Lenited where none is licensed is E103. Base form where lenition is required is E102. Lenited spelling of a word that cannot lenite at all is E104. A form matching no paradigm of a known lemma is E105. Declaring anything outside the base form is E107.

A member reached through a foreign origin, such as ó "some-package" or ó "file.js", keeps its exact spelling and is never lenited. You don't get to rename someone else's API just by importing it, so a borrowed name has no mutation slot at all rather than an empty one.

Eclipsis (urú) gets a related but asymmetric treatment. foirmDe(lemma, FOIRM.URAITHE) always throws, because no syntactic slot in the language demands an eclipsed form of anything. But an eclipsed surface form is still recognised on sight, purely so it can be refused by name instead of falling through to "unbound identifier." Writing scríobh mbaile is correct Irish for the eclipsed form of baile. Reporting E101 for it would be a worse answer than E108, which says plainly that eclipsis is real Irish grammar with no programming meaning assigned to it here. --paraidím prints every identifier's eclipsed form too, labelled "gan bhrí" (without meaning), so the gap stays visible instead of silent.

All of this mutation logic lives in one file, morphology.js, that knows nothing about programming at all. It only answers questions about Irish orthography: can this word lenite, what is its lenited form, which lemma could this eclipsed form have come from. The semantic layer asks it questions. It never asks the semantic layer anything back. That separation is what keeps the boundary clean: mutation is a property of a word, government is a property of a syntactic position, and agreement is the check that joins the two.

Bindings, types, and state

seasmhach (immutable) and sealadach (mutable) split the way Irish is and bí split: essence against accident. A struct field is always a seasmhach shape. Only a sealadach binding, or a sealadach parameter, can change, and it changes with a command rather than assignment:

cuir <luach> ar <sprioc>

cuir is a command. It is E502 inside a feidhm and E510 against a seasmhach target. Its target lenites through the same ar government used everywhere else. The target does not have to be a bare binding either: the analyzer walks any possessive chain back to its root binding and checks mutability there, so cuir luach ó ch + 1 ar luach ó ch is legal on a field of a struchtúr sealadach parameter, even though the field itself is written in the ordinary immutable struct form.

Primitives: Uimhir, Teaghrán, Bool, Neamhní, Iasacht (anything crossing the JS boundary, untyped, and the reason the copula matters at all: x is Uimhir is a real question against a borrowed value, not a tautology), Liosta(T). A struchtúr is a record with typed, all-required fields. E203 is an unknown field. E204 is a missing one.

A list literal widens when its items disagree in type. [1, "a", 3] has no common type, so it becomes Liosta(Iasacht) rather than an error, because that is exactly what Iasacht is for: a category the compiler is deliberately declining to track. This widening also covers a driver's variadic parameter list, such as [ainm, aois] passed through to a SQL query, which is legitimately heterogeneous and has no sum type it should belong to. Two variants of the same sum, though, meet at the sum instead of widening all the way to Iasacht. [Ceart { luach: 1 }, Easpa { cúis: "x" }] types as Liosta(Toradh), because both arms share an actual common type once sum types exist. The same join decides the type of a má/mura chain used as an expression: one arm producing Ceart and the other producing Easpa types as Toradh, not as a mismatch. Two branches that share no supertype at all are what E211 is reserved for. No real program reaches it: the one case that looked like a fit turned out to be the heterogeneous parameter list above, so the code stays reserved rather than firing on legitimate code.

suim declares a closed choice between named variants, each one a struct body under its own name. Ceart { duine: Duine } is the same literal syntax a struct already had, with no new grammar written for it. A variant field typed Iasacht is E213: a sum is a closed statement of what a value may be, and a payload of unknown category inside it is a sum that has not finished being written. A struct field can still be Iasacht, because a record never claimed to enumerate anything. A sum with fewer than two variants is E214, because a choice needs at least two things to choose between.

más Ceart toradh { ainm ó dhuine ó thoradh } mura { cúis ó thoradh }

más narrows. Inside the affirmative branch, the value is treated as that variant. Inside the negative branch, but only when the sum has exactly two variants, the value is treated as the other one, because "not Ceart" only names something real when there is exactly one alternative for it to be. With three variants or more, the negative branch keeps the whole sum type and the program has to ask again. That is a permanent limit rather than a gap waiting to be filled: naming the complement of one variant among several would need anonymous unions, and the language does not have them.

Narrowing is recognised by shape, not by a symbol-table lookup, the same way the parser tells a copular clause apart from an ordinary condition in the first place. A copular clause is a particle, a predicate, and a subject with no linking verb between them, so más Ceart toradh reads as two juxtaposed words after the particle. Two juxtaposed words are otherwise illegal here, so seeing that shape is enough on its own to recognise it, with no lookup needed to decide what kind of clause it is. The analyzer only narrows when the recognised subject is a plain identifier bound to a seasmhach value of sum type, and only when the named variant genuinely belongs to that sum. A sealadach binding never narrows, because it could be reassigned inside the very branch the narrowing would apply to, and a narrowing that a later cuir can invalidate was never true in the first place.

is classifies. tá and bhfuil ask whether something is present. Neither ever substitutes for the other. bí's written form must agree with the particle governing its clause: tá after má, bhfuil after mura. Getting the form backwards is E512. The meaning never changes, only the shape does. The copula fuses with its particle the same way: má plus is becomes más, and mura plus is becomes mura or murab before a vowel. Writing them apart, or choosing the wrong allomorph, is E517. Whichever particle governs a condition is tracked as compiler state for exactly the length of that condition and then restored afterward, so a copula nested inside the subject of an outer condition is never accidentally checked against the outer particle instead of its own.

Mood and aspect: verbs have a grammatical type

Every verb is one of three moods, and mood is part of the verb's type. It is not a flag bolted onto some other type underneath.

feidhm(Uimhir) -> Uimhir     // indicative: mentioned, called with parens
gníomh(Teaghrán)              // imperative: obeyed, bare command, no result
ag gníomh(Iasacht)             // imperative, ongoing — see aspect below

A gníomh is only ever obeyed, never mentioned. Its bare name, or calling it with parentheses, is E501. Its type never matches a feidhm parameter, and it cannot declare a return type at all (E404). A command written inside a feidhm is E502: the indicative states things, the imperative does them, and those are different jobs. A value produced but never used inside a feidhm body is E503.

Because mood and aspect are part of a verb's type, a higher-order parameter can demand a specific one. gníomh faoiDhó(g: gníomh(Teaghrán), xs: Liosta(Teaghrán)) only accepts an imperative of that exact shape. Passing a feidhm there instead, even one whose parameter list matches, is a type mismatch (E201). The verb-type grammar mirrors an ordinary declaration with the name abstracted away, because that is exactly what a type is.

a <briathar> nominalises a declared verb so it can be passed where a value is expected: déan a fhógair ar dhaoine. Without a that is E501. Two identifiers written side by side are not otherwise a legal expression in R336, which is what lets this be recognised by shape rather than by a keyword. When the parser sees the identifier a immediately followed by another identifier, it checks whether that second word, delenited if it looks lenited, is a known verb. If it is, the pair becomes a verbal noun. If it is not, a simply falls back to being an ordinary identifier, which is why a seasmhach = 3 still compiles and scríobh a still works afterward. a was deliberately never made a keyword: two bare identifiers together are otherwise meaningless, so the shape of the input carries the decision instead of a lookup table. a before something that genuinely is not a verb is E513.

déan a fhógair ar dhaoine

déan … ar … is the one place in the language that infers anything. It checks the verb's single parameter type against the collection's element type, then runs the verb once per element. This always compiles to a plain for…of loop, never to Array.prototype.forEach, because R336 has no closures to hand a callback and because an ongoing verb has to be awaited once per iteration, in order, which a callback-based iterator cannot express cleanly. If the verb passed to déan is itself ag, the whole command becomes ongoing, the loop body gets an await, and the surrounding verb must itself be ag or the analyzer reports E504 exactly as it would for any other tar éis used outside an ongoing verb. déan and cuir are the only two built-ins that ever take an ar phrase. Any user-declared verb taking one anyway is E515, and calling déan without one is E514.

Aspect is orthogonal to mood. ag marks a verb as ongoing and compiles to async. tar éis <glao> completes an ongoing call and yields its result, compiling to await. The result of calling an ag verb is not a value until it has been completed. Using it directly is E505. tar éis only works inside a verb itself marked ag (E504 otherwise), and only on something that is genuinely ongoing (E508 otherwise). A command given to an ongoing verb is completed automatically, but the calling verb must itself be ag for that to be legal.

The third mood, saor (autonomous), has no agent to command at all. Its declaration names the root, and the compiler derives the autonomous surface form by conjugating that root, the same way it derives a lenited form. A monosyllabic root like scríobh or cuir is first conjugation: the ending is -tar after a broad stem and -tear after a slender one, decided by the stem's last vowel. A stem ending in -th or -gh absorbs the ending's leading sound rather than doubling it, so caith becomes caitear, not caithtear. A polysyllabic root ending in -(a)igh, such as ceannaigh, is second conjugation, and takes -aítear or -ítear once the -igh is stripped. A smaller class of second-conjugation roots syncopates: the unstressed vowel of the final syllable drops before the vowel-initial ending is attached, so oscail becomes oscl- first and then osclaítear, and fógair becomes fógr- first and then fógraítear. Whether the resulting stem counts as broad or slender is judged after syncopation, not before, because syncopation is exactly what changes it. A short table of Irish's eleven genuinely irregular verbs, including bí, faigh, abair, and tabhair, is checked before any of these rules run at all.

saor liostaigh(mír: Teaghrán) { scríobh mír }
// …
liostaítear "arán"      // the only legal way to say it

The root itself can never be commanded (E518, the mirror image of E501), because the imperative root speaks to an agent and the autonomous has none. The past autonomous is derived the same way, but it exists purely to be recognised and refused by name (E519). R336 has no tense anywhere, and reporting "unbound identifier" for a form that is correct Irish would be a worse answer than naming the form and saying plainly that there is no past tense here to write it in.

Modules and the boundary

ó "./file.r336" and ó "some-package" are the same relation, origin, with different consequences depending on what's on the far side. A .r336 path is native: type, mood, and aspect all survive the crossing untouched, reached through the ordinary ó relation like any local possession. Anything else is Iasacht: untyped, never lenited, its category knowable only at runtime with is.

A signature, built by siniu(), lists every top-level binding a module exports that it did not itself re-export from somewhere else, along with its kind (value, feidhm, or gníomh), its type, and whether it is sealadach. It also carries the module's own county, purely so that --graf can print it later. Nothing on the importing side ever reads that county, because reading a module's vocabulary is not the same as trading with it.

Codegen gives each imported module a short alias, __m0, __m1, and so on, and requires it once at the top of the file. An ordinary borrowed value binds as const. A sealadach export is handled differently: it is exposed through Object.defineProperty with a getter, so the importer always reads the exporting module's current value rather than a snapshot taken at import time. That live binding is what lets a module-level stór variable, assigned once inside a tosaigh action, be read correctly by every other file that imported the module before tosaigh ever ran.

An imported gníomh joins the importing file's own vocabulary directly and is called unqualified, as a bare command: fáiltigh "Cáit". It cannot take a possessor, because a command is not a noun phrase. fáiltigh ó fhoclóir("Cáit") is E516. The design notes describe this as the same thing Irish does with a borrowed verb: nobody says "the borrowed verb fáiltigh," people just say fáiltigh, natively conjugated and folded straight into the vocabulary. An imported value or feidhm is reached the ordinary possessive way instead: beannaigh ó fhoclóir("Oisín").

The same lemma exported unqualified by two different imported modules is ambiguous, since there is no qualifier to disambiguate it with. That is E106, and the fix is to rename one of them. A local declaration that collides with an import is the ordinary E208, with no special case written for imports at all.

Provenance

as <contae> places a module, or a struct or sum type, in one of 32 Irish counties grouped into four provinces. It controls which files may read a placed type's fields through ó. Two rules sit on top of ordinary type checking rather than being woven into it. Construction, passing arguments, and returning values are never checked against county at all: a placed value can travel anywhere in a program. Only reading a member through ó is checked, and only against the county of the file doing the reading, not the value's own county. That single choice is what lets a module declared in exile (no as at all) build placed structs out of raw primitives it was handed and pass them on untouched, without ever being allowed to open one itself.

This is a deliberately strange feature layered on top of everything described above rather than mixed into it, and it has its own page with the rest of the mechanic: exile, treaties, and the fixed list of rivalries no treaty can lift. See Counties.

Diagnostics architecture

Diagnostics are collected, not thrown one at a time. A Bailitheoir (diagnostics.js) accumulates every problem found during a compile into a list. The pipeline only throws once, wrapping the whole list in a single bundle, after the analyzer has walked as much of the file as it safely can. That is why one bad file can report several unrelated problems from a single run instead of stopping dead at the first mistake it finds.

Every diagnostic is a stable numeric code. earraid(cod, ionad, ...args) looks the code up in a table of message-building functions and attaches the source position where it fired. The code is the contract that tests and tooling are allowed to depend on. The Irish wording behind it is explicitly not part of that contract: the project's own notes call for the wording to be reviewed by a fluent speaker and treat it as something that can still change without breaking anything.

RangeSubject
1xxmorphology: mutation, form, resolution, modules
2xxtypes
3xxthe copula and bí
4xxlexing and parsing
5xxmood, aspect, the copula's form, the autonomous verb
6xxprovenance: province, county, exile, treaty

Two codes are reserved on purpose: each has a message and deliberately no way to fire. E211 was made reachable in one release and made unreachable again in the very same release, once a real program showed that the case it was meant to catch was actually a legitimate heterogeneous parameter list rather than a mistake. E506 described a má-as-expression failure the backend no longer produces, once multi-statement branches started being hoisted into a temporary instead of failing outright. A reserved code that later acquires a real test case is treated as a bug in the reservation, not a green light to let it start firing.

Even the diagnostic text is Irish, and it follows its own grammar rather than a second copy of it. E201's message runs its expected-type phrase through the same h-prefixation rule that governs ordinary program text before a vowel-initial word (le hUimhir, not le Uimhir), using the language's own morphology helper rather than duplicating the rule inside the diagnostics file.

Every diagnostic has a matching case file under examples/earraidi/, written to fail with exactly that code and no other. A dedicated test walks the table in both directions: every code has a case, and every case fails with only the one code its filename claims. That pairing is enforced mechanically instead of kept as a convention, because it used to drift. Twenty-three of sixty codes had no case file at all the first time anyone counted.

Tooling and tests

The CLI (bin/r336c.js) runs the same pipeline five different ways. With no flag it compiles a file, or every .r336 file under a directory, to sibling .js files. --rith compiles and runs the result, awaiting an exported príomh if the file declares one. --amharc prints the generated JavaScript without writing it. --crann prints the abstract syntax tree. --paraidím prints every grammatical form of every top-level binding, including the copula's own paradigm laid out against a real consonant-initial and vowel-initial type name pulled from the file itself, so the allomorph rules are visible against actual data rather than a placeholder. --graf prints the module graph together with each type's province, the treaties in force, and which counties this particular file could never reach even with a treaty.

The test suite is organised along the same seams as the compiler rather than by file. test/run.js covers morphology, types, and the core grammar. test/contae.js covers provenance on its own. test/suim.js covers sum types. test/feidhmchlár.js compiles the real example application straight off disk, because it is the one suite exercising real files rather than inline strings, and it exists specifically to catch the day someone "simplifies" bealaí.r336 by reading a field directly instead of going through the accessor that keeps the province boundary honest. test/earraidi.js is the diagnostics corpus check described above. Negative tests, ones that are supposed to fail with one specific code, are treated as the most valuable tests in the suite rather than an afterthought added once the happy path works.

Design discipline

Every unusual piece of syntax has to answer six questions before it's accepted into the language: what actual Irish grammatical phenomenon inspired it, what relationship that phenomenon expresses in Irish, what programming relationship resembles it, whether the analogy still holds up when used repeatedly rather than just once, whether the compiler actually needs to understand the grammar to implement the feature, and whether the feature earns its own complexity. A proposal that fails this test gets written up and rejected on the record rather than quietly dropped and forgotten. Rejection is treated as a normal and expected outcome of the process, not a failure of it.

Two features are named exceptions rather than hidden ones. The county system is a deliberately strange, rigorously enforced bit: as itself is real Irish government, but the specific list of 32 names and the rivalry table are not a linguistic phenomenon at all, and the project says so plainly rather than dressing them up as grammar after the fact. Sum types are treated as ordinary engineering in the same spirit, with only their eliminator, the copula, actually claimed as grounded in Irish.

A handful of invariants are meant to hold everywhere, and they are checked by tests rather than left as intentions. The backend never sees a mutation form, a county, a province, or a sum's own name. No driver-specific vocabulary, such as sql, sqlite, or prisma, appears anywhere in the front end. Every grammatical government relation routes through one function. The eclipsed slot stays permanently empty. Every AST node and internal identifier in the compiler is named in Irish, not English.

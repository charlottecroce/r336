Store

A declared type may have a table behind it. Rows come back already typed, and the table's name and columns come from the declaration rather than from a string you wrote.

The marker stór

struchtúr Duine firinscneach stór as Corcaigh {
    ainm: Teaghrán
    aois: Uimhir
}

One word in the declaration says this type is stored. The modifier order is fixed - name, gender adjective, marker, provenance - and any other order is E401. The adjective agrees with the noun, so it stays beside it; the marker is engineering rather than Irish, so it sits outside the grammatical material; provenance closes, as it already did. See Structures for the slot list.

A marked type must have a county (E610): a table has to be somewhere.

stór is not a reserved word. It is read as an ordinary identifier in that one slot and nowhere else, which is what lets the same file go on using stór as the name of a binding - as every example on this page does. faigh is reserved, because it takes a type where an expression would otherwise begin and there is nothing for a lookahead to decide against. The cost, paid knowingly: no verb may be named faigh.

Only a structure can be marked. A suim cannot, and there is no code for it because the grammar has nowhere to put it - the same answer E509 gives methods. A sum does not enumerate rows; a table is a possession of an identified thing.

The table name

Duine reads and writes the table duine. Lowercased, fadas kept, and never pluralised.

Pluralisation in Irish is not a rule the compiler could apply. duine becomes daoine, which is suppletive - no rule reaches it - and it is also the first word anyone tries. Guessing here would be confidently wrong on the worst possible example, so the compiler does not guess. If your table is called daoine, reach it through the untyped path instead.

The columns are the declared field list, in declaration order. There is no second place to write them, deliberately: a column list that could drift from the type's fields would be a second source of truth.

Reading faigh T as S

ag gníomh liostaigh(stór: Iasacht) {
    daoine seasmhach: Liosta(Duine) = tar éis faigh Duine as stór
    déan a bheannaigh ar dhaoine
}

Every row of the type's table, as a Liosta(T), already carrying the tag is reads. The result is ongoing, so it needs tar éis to complete it (E505) inside an ag verb (E504) - the ordinary aspect rules, with nothing added for this feature. Naming a type that has no table is E611.

as, and not the alternatives, for three reasons. ar introduces a verb frame, and déan and cuir are the only built-ins that take one; keeping that sentence true was worth a preposition. ó would parse as a possessive chain - a member read of stór - which is the opposite of what is meant. And as is right on the Irish anyway: a row comes out of a store. It demands the base form, so the government table did not grow, and as shtór is E104 through the path that already existed.

Writing cuir V i S

ag gníomh cláraigh(stór: Iasacht, duine: Duine) {
    cuir duine i stór
}

One row, from a typed value, into the type's own table. This is a second prepositional frame on cuir rather than a new command, so it inherits the mood and aspect rules already in force: a command inside a feidhm is E502, a write outside an ag verb is E504, a target that does not name a store is E511, and a type with no table is E611 from this side too.

Unlike cuir … ar …, the write needs no mutable target. ar assigns to a binding and so refuses a seasmhach one (E510); i puts a value into something passed in as an argument, where there is no binding to protect.

i is the preposition of going into, and it eclipses its complement - which is what gave eclipsis its first real syntactic slot in the language. It also chooses its own shape from the word after it, i with eclipsis before a consonant and in with the base form before a vowel, exactly as más and murab do. See Grammar.

cuir d i gcuntas   // consonant: i + eclipsis
cuir d in áit      // vowel: in + base form
cuir d i stór      // st- resists eclipsis, so nothing changes

One row per call. cuir … i … is a frame and not a verb, so déan cannot distribute it over a list, so bulk writing is not expressible - and a transaction story is not owed until it is.

A table claims a county

An ordinary placed structure or sum claims a whole province, and there are four. A stored type claims a single county, and there are 32.

ClaimGranularitySlots
placed struchtúr / suimprovince4
stór struchtúrcounty32

A type is the vocabulary of a region: saying Duine is from Corcaigh says what a whole part of the program is about, and takes An Mhumhain with it. A table is a building in one town. It is a smaller thing, so it claims a smaller place, and that asymmetry is the whole content of the rule.

This is not an exemption. The two claims collide in both directions: a table in Corcaigh blocks any ordinary type from claiming An Mhumhain, and an ordinary type in An Mhumhain blocks a table anywhere in Munster. Either way it is E603, and declaration order does not decide it. Two tables in one county is E612.

So 32 is a ceiling rather than a budget. It is reachable only by a program with no ordinary placed types at all, and a single ordinary type costs a whole province's worth of counties.

One consequence arrives free. At county granularity, two rival counties can both hold a table - and then a file from Corcaigh reading Ciarraí's rows is E609, which no treaty lifts, while a file anywhere else needs a treaty and can never sign with both. No file in such a program can read both tables. See Counties.

The shape of a database program

The store abstraction is Iasacht, Iasacht is in exile, and a placed file may not read a member off an exiled value (E601). So opening a store and declaring a placed type cannot happen in the same file, and a program splits in two:

FileDoes
exiled shellopens the store, creates the schema, calls into the core
placed coredeclares the stored type, runs faigh and cuir, reads fields off rows

That split is older than this feature and did not move. What changed is what can cross it. faigh needs the store only as an argument, and passing an argument is not a member read, so the conversion from untyped rows to a declared type now happens in the core where the type lives, instead of being hand-written in the shell.

What is deliberately not here

AbsentWhy
Generated schemas The compiler will not emit CREATE TABLE from field types. That needs a type-to-column-type mapping, which is another language's vocabulary shipped inside this compiler. Write the schema by hand, through the untyped path, where the seam is visible.
Filtering faigh Duine as stór is every row. A predicate form is the same shape as the map verb the language has also not built, and it would be built for its own reasons rather than as a side effect of a database feature.
Bulk writes and transactions Not expressible, and so not owed.
A missing-row type faigh returns a list, so emptiness is representable and "this one row is not there" is not. Rather than invent an affliction every read would carry, céad on an empty list refuses: nothing hands R336 an absent value wearing a declared type.

What the runtime does answer is disagreement. Before a read or a write, the declared columns are checked against the table on disk, and a column that is not there is refused by name. An extra column on disk stays invisible, because a structure states every field it has and a row with an unfielded extra is not a value of that type.

Why this exists, and what it is

The reading is Irish. stór is an ordinary noun, faigh X as Y and cuir X i Y are ordinary Irish, as is correctly ungoverned by lenition and i correctly eclipses. The mechanism is a registry, and a registry is exactly what the design rules exist to refuse. So this is a deliberate engineering feature with an Irish reading, labelled as one in the source, in the same way the county system and sum types are - and then enforced as strictly as anything that is grammar. See the Developer Guide.

What it did not have to teach anything: aspect, government, the county rules, type equality, the morphology library, the module graph, and the runtime prelude. A stored structure emits byte-for-byte what an unmarked one emits, and there is a test that compares the two whole programs to prove it.
